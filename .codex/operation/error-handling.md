# 예외 처리 개요

## 기본 원칙

- 예외는 실패를 숨기지 않고 호출자가 이해할 수 있는 형태로 변환한다.
- Controller에서 예외를 문자열로 직접 반환하지 않는다.
- Service는 비즈니스 실패를 표현하고 HTTP 응답 객체를 만들지 않는다.
- 예상 가능한 실패와 예상하지 못한 시스템 오류를 구분한다.
- 모든 외부 오류 응답은 공통 응답 형식을 따른다.

## 처리 흐름

```text
요청
  ↓
DTO 검증
  ↓
Guard 인증·권한
  ↓
Controller
  ↓
Service / Domain 예외
  ↓
전역 Exception Filter
  ↓
HTTP 오류 응답 + 구조화 로그
```

## 예외 분류

- 입력 예외: DTO 형식·범위·필수값 오류
- 인증 예외: 토큰 누락·만료·위조
- 권한 예외: 리소스 접근 권한 부족
- 도메인 예외: 운동 기록 상태·목표·소유권 규칙 위반
- 리소스 예외: 대상 데이터 없음
- 시스템 예외: DB·외부 서비스·예상하지 못한 오류

## 처리 원칙

- 도메인 예외는 의미 있는 에러 코드로 변환한다.
- 시스템 예외는 내부 로그에 원인을 기록하고 외부에는 일반 메시지만 반환한다.
- 같은 요청에서 여러 오류가 발생하면 API 계약에 정의된 우선순위를 따른다.
