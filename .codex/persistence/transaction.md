# 트랜잭션 규칙

## 트랜잭션이 필요한 경우

- 운동 기록 저장과 관련 통계 갱신
- 목표 달성과 캐릭터 상태 변경
- 여러 테이블을 함께 생성·수정·삭제
- 중복 생성 방지가 필요한 상태 변경

## 책임

- 트랜잭션 경계는 Application Service가 결정한다.
- Repository는 저장소 작업을 수행하되 전체 유스케이스 흐름을 소유하지 않는다.
- 외부 API 호출은 DB 트랜잭션 안에 오래 묶지 않는다.

## 주의점

- 트랜잭션 내부에서 느린 네트워크 작업을 실행하지 않는다.
- 재시도 시 중복 저장 가능성을 검토한다.
- 실패 시 부분 저장이 남지 않는지 테스트한다.
- 격리 수준과 동시성 정책은 실제 충돌 시나리오에 맞춰 결정한다.
