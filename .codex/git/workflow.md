# Git 작업 흐름

## 작업 시작

1. 현재 브랜치와 작업 트리를 확인한다.
2. 기존 변경사항을 확인하고 사용자 변경을 보존한다.
3. 관련 문서와 구현 범위를 정한다.

## 작업 중

- 작은 단위로 구현하고 자주 검증한다.
- 기능·문서·설정 변경을 구분한다.
- 의미 있는 상태에서 커밋한다.
- 비밀키·환경변수·빌드 결과를 커밋하지 않는다.

## 커밋 전

```bash
git status
git diff --stat
git diff --cached --stat
npm run build
npm test
```

작업 종류에 따라 관련 테스트와 lint를 추가로 실행한다.

## 브랜치

- 현재 초기 문서 작업은 `main`에 기록한다.
- 기능 개발이 시작되면 `codex/` 접두사 브랜치를 우선 사용한다.
- 하나의 브랜치는 하나의 기능 또는 밀접한 작업 범위만 담당한다.
- 강제 push, reset, rebase는 명시적인 승인이 없으면 사용하지 않는다.
