# 커밋 규칙

## 메시지 형식

```text
<prefix> : <한글 변경 요약>
```

현재 `main`에서는 이슈 번호를 강제하지 않는다.

## Prefix

- `feat`: 신규 기능·도메인·API
- `fix`: 일반 버그 수정
- `refactor`: 동작 변경 없는 구조 개선
- `hotfix`: 긴급 운영 수정
- `docs`: Markdown·API 계약·아키텍처·프로젝트 문서
- `chore`: 의존성·설정·빌드·도구 변경

예시:

```text
feat : 운동 기록 등록 API 추가
docs : Prisma 영속성 규칙 추가
chore : 테스트 실행 설정 변경
```

## 분리 원칙

- 하나의 커밋은 하나의 큰 의도를 가진다.
- 문서, 설정, 기능 구현은 가능하면 분리한다.
- API와 도메인 구현이 함께 변경되면 요구사항 단위로 나눈다.
- 커밋 전 staged diff가 메시지 한 줄로 설명되는지 확인한다.
- 관련 테스트는 기능 커밋에 포함할 수 있다.

## 금지 사항

- 의미 없는 `작업 내용 정리` 메시지 사용
- 서로 무관한 기능을 한 커밋에 묶기
- 검증하지 않은 변경을 완료된 것처럼 커밋
- 사용자 변경사항을 확인 없이 stage
