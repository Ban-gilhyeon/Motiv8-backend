# 인증 도메인

## 담당 범위

사용자 계정, 인증, 인가, 개인정보 접근을 관리한다.

## 핵심 개념

- User: 운동 데이터와 목표의 소유자
- Authentication: 사용자의 신원을 확인하는 과정
- Authorization: 요청한 자원이 사용자 소유인지 확인하는 과정

## 비즈니스 규칙

- 인증된 사용자만 개인 운동 데이터를 접근할 수 있다.
- 사용자는 자신의 기록만 생성·수정·삭제·조회할 수 있다.
- 다른 사용자의 ID를 알아도 데이터를 조회할 수 없어야 한다.
- 외부 입력은 DTO 검증을 거쳐야 한다.
- 개인정보와 인증 정보는 응답에 불필요하게 노출하지 않는다.

## 사용자 흐름

1. 사용자가 회원가입 또는 로그인을 요청한다.
2. 서버가 입력값과 계정을 검증한다.
3. 서버가 인증 토큰을 발급한다.
4. 보호된 API는 토큰과 사용자 소유권을 검증한다.

## 인증 토큰 정책

- Access Token은 짧은 유효기간을 사용하고 API 요청의 `Authorization: Bearer` Header로 전달한다.
- Refresh Token은 Access Token보다 긴 유효기간을 사용한다.
- 서버에는 Refresh Token 원문이 아니라 해시를 저장한다.
- Refresh Token은 Secure Storage를 사용할 모바일 앱을 우선 고려한다.
- 회원가입 성공 시 바로 사용할 수 있도록 Access Token과 Refresh Token을 발급한다.
- 회원가입 성공 시 기본 Profile을 함께 생성한다.

## 예외 상황

- 존재하지 않는 계정 로그인
- 잘못된 비밀번호 또는 만료된 토큰
- 인증 없이 보호 API 접근
- 다른 사용자의 리소스 접근
- 중복 이메일 또는 사용자 식별자

## 결정이 필요한 사항

- Refresh Token 회전과 로그아웃 시 폐기 정책은 무엇인가?
- 탈퇴 시 운동 기록을 함께 삭제할 것인가?
